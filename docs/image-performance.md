# Responsive image delivery

`npm run dev` and `npm run build` prepare image files before starting Next.js.
The same scripts work with pnpm. `npm run images:prepare` runs preparation alone.

`scripts/prepare-images.mjs` preserves the source images and creates WebP sizes
from 96 to 1920 pixels, capped at each source's width, in
`public/images/optimized/`. It also creates lossless, tightly cropped full and
icon versions of the supplied official logo. Transparent illustrations keep
their alpha channel. Photos retain their existing crops and content.

The generated manifest is committed so type checking can run before a build.
Image variants are ignored and regenerated by the build, including the Pages
workflow. Content hashes in their filenames invalidate old image URLs when a
source changes. Existing variants are reused locally.

`components/ui/Image.tsx` renders native `img` markup on the server, including
real width descriptors, layout dimensions, lazy loading, and responsive
preloads for priority images. It does not ship an image component to the
browser or require a runtime optimization endpoint. This works identically
on the Next.js server and GitHub Pages. Keep source paths free of the deployment
base path; the shared image loader adds it once.

After adding or replacing an image, run image preparation and commit the updated
manifest. The responsive-image tests check generated files, source-size caps,
quality variants, and fallback URLs. The asset and width-sweep tests check
rendering and layout while images are still pending.

## Verification, 25 October 2026

Cold browser contexts, Edge/Chromium, DPR 1. All page images were deliberately
loaded, including lazy images, so these are full-page image payloads rather
than initial-load transfer totals. Baseline: deployed commit `cb44e8d`.
After: the production static export with the same routes and viewport sizes.

| Page | Width | Before | After |

| Home | 1440 | 5,171,312 B | 454,710 B |

The existing 150 KiB gzip JavaScript budget passes on every published route
and the missing-page control. Homepage modules are 148,596 bytes; the largest
route total is 153,415 bytes. The budget was not raised. Unused display-font
preloads were disabled, and hero text renders immediately without a delayed
entrance animation.
